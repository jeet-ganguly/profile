# Linux Firewall Management (iptables) Notes

> Linux firewall management controls how packets enter, leave, and move through a system.
> Linux firewalling is implemented using **Netfilter** inside the kernel and managed using **iptables**.

`iptables` is a user-space utility that allows administrators to configure packet filtering rules.

# 1. Introduction to Netfilter and iptables

Linux firewalling works through:

```text
Netfilter → Kernel framework
iptables → User-space utility
```

Relationship:

```text
User Command
      ↓
iptables
      ↓
Netfilter
      ↓
Kernel Packet Filtering
```

---

## Why Use iptables?

iptables helps:

* control incoming traffic
* control outgoing traffic
* block malicious IPs
* allow only required services
* perform NAT
* modify packets
* log suspicious connections

---

# 2. Tables in iptables

A **table** is a collection of chains that serves a specific purpose.

The three major tables:

1. Filter
2. NAT
3. Mangle

---

# Filter Table

Used for:

```text
Packet filtering and access control
```

Contains:

* INPUT
* OUTPUT
* FORWARD

---

# NAT Table

Used for:

```text
Network Address Translation
```

Contains:

* PREROUTING
* POSTROUTING
* OUTPUT

---

# Mangle Table

Used for:

```text
Modify packet headers
```

Contains:

* INPUT
* OUTPUT
* FORWARD
* PREROUTING
* POSTROUTING

---

# Table Summary

| Table  |             Purpose | Chains                                          |
| ------ | ------------------: | ----------------------------------------------- |
| Filter |    Packet filtering | INPUT, OUTPUT, FORWARD                          |
| NAT    | Address translation | PREROUTING, POSTROUTING, OUTPUT                 |
| Mangle | Packet modification | INPUT, OUTPUT, FORWARD, PREROUTING, POSTROUTING |

---

# 3. Chains in iptables

Chains define where rules are applied.

---

## a) INPUT Chain

Used for:

```text
Incoming packets destined for local machine
```

Example:

* SSH connection to your server

---

## b) OUTPUT Chain

Used for:

```text
Packets generated by local machine
```

Example:

* Browser requesting webpage

---

## c) FORWARD Chain

Used for:

```text
Packets passing through system
```

Usually used:

* routers
* gateways
* VPN servers

---

## d) PREROUTING Chain

Packet enters system:

```text
Before routing decision
```

---

## e) POSTROUTING Chain

Packet leaves system:

```text
After routing decision
```

---

# Chain Summary

| Chain       | Purpose          |
| ----------- | ---------------- |
| INPUT       | Incoming packets |
| OUTPUT      | Outgoing packets |
| FORWARD     | Routed packets   |
| PREROUTING  | Before routing   |
| POSTROUTING | After routing    |

---

# 4. Packet Flow in iptables

Incoming packets move through several chains.

Basic flow:

```text
Incoming Packet
        ↓
PREROUTING
        ↓
Routing Decision
     ↙      ↘
INPUT      FORWARD
   ↓           ↓
Process     POSTROUTING
   ↓
OUTPUT
   ↓
POSTROUTING
```

# 5. Rule Targets

When packet matches a rule:

iptables performs an action called target.

---

## a) ACCEPT

```text
Allow packet
```

Stops processing and permits traffic.

---

## b) DROP

```text
Silently discard packet
```

No response sent.

---

## c) REJECT

```text
Drop packet and send response
```

Examples:

* connection refused
* ICMP unreachable

---

## d) LOG

```text
Log packet information
```

Usually appears:

```bash
/var/log/messages
```

or:

```bash
/var/log/syslog
```

---

# Rule Target Summary

| Target | Behavior           |
| ------ | ------------------ |
| ACCEPT | Allow traffic      |
| DROP   | Discard silently   |
| REJECT | Discard with reply |
| LOG    | Record event       |

# 6. Basic iptables Syntax

General structure:

```bash
iptables [action] [chain] [condition] [target]
```

Example:

```bash
iptables -A INPUT -s 192.168.1.5 -j DROP
```

Meaning:

| Component | Meaning       |
| --------- | ------------- |
| `-A`      | Append rule   |
| `INPUT`   | Chain         |
| `-s`      | Source IP     |
| `-j`      | Target action |

---

# Common Actions

| Option | Meaning        |
| ------ | -------------- |
| `-A`   | Append         |
| `-I`   | Insert         |
| `-D`   | Delete         |
| `-L`   | List           |
| `-F`   | Flush          |
| `-P`   | Default policy |

---

# 7. Common Firewall Commands

## a) List Current Rules

```bash
sudo iptables -L
```

---

## b) List with Numeric Addresses

```bash
sudo iptables -L -n
```

---

## c) View Line Numbers

```bash
sudo iptables -L --line-numbers
```

---

## d) Set Default Policies

Allow INPUT:

```bash
sudo iptables -P INPUT ACCEPT
```

Allow FORWARD:

```bash
sudo iptables -P FORWARD ACCEPT
```

Allow OUTPUT:

```bash
sudo iptables -P OUTPUT ACCEPT
```

---

## e) Block Incoming IP

```bash
sudo iptables -A INPUT -s <ip-address> -j DROP
```

Example:

```bash
sudo iptables -A INPUT -s 10.0.0.5 -j DROP
```

---

## f) Block Entire Subnet

```bash
sudo iptables -A INPUT -s 192.168.1.0/24 -j DROP
```

---

## g) Block Outgoing Connection

```bash
sudo iptables -A OUTPUT -d <ip-address> -j DROP
```

---

## h) Block Port Access

```bash
sudo iptables -I INPUT -p tcp --dport <port> -j DROP
```

Example:

```bash
sudo iptables -I INPUT -p tcp --dport 80 -j DROP
```

---

## i) Block Specific IP from Accessing Port

```bash
sudo iptables -I INPUT -p tcp --dport 22 -s <IP> -j DROP
```

Example:

```bash
sudo iptables -I INPUT -p tcp --dport 22 -s 10.0.0.5 -j DROP
```

# 8. Managing Rules

## a) Save Rules

```bash
/sbin/iptables-save
```

Some systems:

```bash
iptables-save > rules.conf
```

---

## b) Clear All Rules

```bash
sudo iptables -F
```

---

## c) Delete Specific Rule

General syntax:

```bash
sudo iptables -D <CHAIN> <RULE-NUMBER>
```

Example:

```bash
sudo iptables -D INPUT 2
```

---

## d) Insert Rule at Specific Position

```bash
sudo iptables -I INPUT 1 -s 10.0.0.5 -j DROP
```

Rule inserted at position:

```text
1
```

# 9. Practical Cybersecurity Examples

## a) Block Attacker IP

```bash
sudo iptables -A INPUT -s 185.220.101.20 -j DROP
```

---

## b) Block SSH Brute Force Attempts

```bash
sudo iptables -A INPUT -p tcp --dport 22 -m recent --name SSH --update --seconds 60 --hitcount 5 -j DROP
```

---

## c) Allow Only Internal Network

```bash
sudo iptables -A INPUT -s 192.168.1.0/24 -j ACCEPT
```

Block others:

```bash
sudo iptables -A INPUT -j DROP
```

---

## d) Log Suspicious Connections

```bash
sudo iptables -A INPUT -p tcp --dport 4444 -j LOG
```

---

## e) Block Reverse Shell Listener Port

```bash
sudo iptables -A INPUT -p tcp --dport 4444 -j DROP
```

---

# 10. Important Notes

* iptables interacts with Netfilter.
* Rules are processed top to bottom.
* First matching rule is applied.
* INPUT = incoming packets.
* OUTPUT = outgoing packets.
* FORWARD = routed packets.
* DROP silently blocks.
* REJECT blocks with response.
* Use `iptables-save` to persist rules.
* Modern Linux distributions often use:

```bash
nftables
```

or:

```bash
ufw
```

as frontend tools.
